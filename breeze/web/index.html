LOCAL ARTIFACTS · LOCAL SERVICE
01

Explore the workflow

Start the scripted demo from the project directory. No model is loaded and no real inference performance is measured.

python serve_breeze.py --demo

Open the service in your browser. A local unauthenticated demo does not need an API key.

02

Bring your model

Use existing quantized Qwen3.5 dense 9B or 27B artifacts. Native inference requires Linux x86-64 and an AVX-512 VNNI/VBMI CPU.

python serve_breeze.py --model /path/to/model.onnx --threads 48

Example thread count: choose for your deployment CPU. Build the native library and provide the local model, configuration, tokenizer, and embeddings first.

BEFORE YOU SHARE IT

A workspace, with boundaries.

Keep local access on loopback. Non-loopback binding requires a server-configured BREEZE_API_KEY. Plan your deployment’s transport security and access controls before exposing the service.

  • Know your capacity One active native request. The bounded queue may reject new work when full. Retry manually when space is available.
  • Keep context intentional The input conversation and requested output must fit the configured context window. Start fresh or lower the output budget when needed.
  • Keep only what you need Breeze does not persist prompts or responses. This page keeps chat and credentials in memory; refreshing clears them. Other deployment components have their own policies.
